# 自我介绍版本记录

本文件按形成顺序保存自我介绍版本。当前口述训练以第二版为准，第一版保留用于回看表达演进。

## 第一版：项目细节展开版（历史初稿）

### 口述稿

面试官您好，我叫吴超文，目前是中山大学计算机相关方向硕士，主要关注 AI 应用开发和后端工程。

我近期围绕公寓租赁业务做了两个 AI 应用项目。主项目是租客侧智能找房助手 AptGuide 3.0，支持自然语言找房、租赁规则咨询、预约看房和租约查询。在这个项目中，我重点关注的是模型如何进入真实业务流程。例如用户提出预约需求时，模型只负责识别意图，系统会先生成待确认动作，用户确认后再由 lease 业务后端执行真实写入；在房源推荐中，我也发现向量检索返回房源卡片并不等于它已经是可预约房源，还需要完成房源身份映射和业务事实校验。

另一个项目是运营侧智能分析助手 AptInsight。它支持将运营人员的自然语言问题转换成 SQL，分析预约、租约、房源和租金数据。我在这个项目中关注的是模型生成结果的安全性和业务正确性：SQL 必须经过 AST 安全校验并通过只读账号执行；同时，即使 SQL 能运行，也要判断指标口径是否正确，例如预约转化率只能基于现有数据作为公寓维度的参考指标，不能包装成精确转化结论。

通过这两个项目，我逐渐形成了一个比较明确的认识：大模型适合负责语义理解、查询规划和结果表达，但真实业务中的身份、权限、状态写入、数据事实和安全校验必须由系统层控制。我也使用 AI Coding 工具提升开发效率，但关键的业务边界、失败分析和评测验证由我负责。希望后续能够继续把 AI 能力和后端工程结合起来，开发更可靠、可验证的业务应用。

### 复盘结论

- 优点：项目技术细节较完整，能够承接 AptGuide 和 AptInsight 深挖。
- 问题：信息密度偏高，口述中记忆点不足；AI Coding 工作方式表达不充分。

## 第二版：大模型应用综合方向（当前定稿）

### 90 秒口述稿

面试官您好，我叫吴超文，目前是中山大学计算机研二在读。我的求职方向是大模型应用开发和后端工程。我希望把 AI 能力接入真实业务流程，并通过系统设计让应用更可控、更可靠。

近期我围绕公寓租赁业务开发了两个 AI 应用。第一个是面向用户的智能找房助手 AptGuide 3.0，支持自然语言找房、租赁规则咨询、预约看房和租约查询。围绕找房、租赁规则咨询和预约看房三个核心场景，我重点处理了模型输出如何受到业务规则和系统流程约束。

第二个是面向管理员的智能分析助手 AptInsight，支持通过自然语言分析房源、预约、租约和租金等业务数据。我主要关注自然语言生成 SQL 后的安全控制，通过 SQL 安全校验和只读权限，限制模型只能查询和解释数据。

在开发过程中，我使用 Codex 辅助需求拆解和计划制定，使用 Claude Code 辅助具体实现，并逐步沉淀出一套适用于长周期 AI 协作开发的工作流，用于管理计划、进度和任务交接。其中关键的业务边界、安全规则和最终验收仍然由我负责。

这些经历让我认识到，大模型更适合负责理解和生成，而业务事实、安全规则和关键操作边界仍然需要由系统控制。我希望后续继续在大模型应用与后端工程结合的方向深入发展。

### 记忆锚点

1. 身份与方向：中山大学计算机研二在读；大模型应用开发和后端工程。
2. AptGuide 3.0：面向用户；找房、规则咨询、预约看房、租约查询；业务规则和系统流程约束。
3. AptInsight：面向管理员；自然语言分析业务数据；SQL 安全校验和只读权限。
4. AI Coding：Codex 计划，Claude Code 实现；沉淀长周期协作工作流；本人负责边界、安全和验收。
5. 总结认识：模型擅长理解和生成，系统控制业务事实、安全规则和关键操作边界。
