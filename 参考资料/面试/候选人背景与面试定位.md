# 候选人背景与面试定位

## 候选人定位

吴超文，中山大学计算机相关方向硕士，面试目标方向包括：

- AI 应用开发；
- Java 后端开发；
- 大模型应用开发；
- Agent / RAG / Text-to-SQL 工程方向。

最合适的面试定位是：

> 一个具备后端工程基础、真实开发过 AI 应用项目、能够使用 AI Coding 提升效率，并开始系统理解 LLM 边界、业务约束和评测验证的成长型工程师。

不要包装为已经负责过完整生产级 Agent 平台、线上治理或大规模业务落地的专家。

## 项目组合

| 项目 | 使用对象 | 面试定位 |
| --- | --- | --- |
| AptGuide 3.0 | 租客 | 主讲项目：自然语言找房与受控业务交互 Agent |
| AptInsight | 运营人员 / 管理员 | 辅助重点：Text-to-SQL 与安全只读分析 |
| lease / 租赁业务平台 | 业务后端 | Java 后端基础与业务事实源 |
| rentHouseH5 / rentHouseAdmin | 租客 / 管理员 | 用户入口和 AI 集成载体 |

## 技术能力主线

面试表达不应停留在技术栈罗列，而应围绕以下理解展开：

1. 业务系统必须保留事实源和权限边界，AI 服务负责智能编排而不是替代核心业务系统。
2. LLM 擅长语义理解、查询规划和结果表达，但不适合直接控制高风险写操作。
3. RAG 和 Text-to-SQL 的难点，不只是“调用模型”，而是数据对齐、安全校验、失败兜底和可评测性。
4. AI Coding 可以提高实现效率，但需求拆解、架构判断、代码审查和结果验收仍由开发者负责。

## 自我介绍参考版本

面试官您好，我叫吴超文，目前是中山大学计算机相关方向硕士。我关注 AI 应用开发与后端工程，近期主要围绕公寓租赁业务做了两个 AI 应用项目。

第一个是租客侧智能找房助手 AptGuide 3.0，用户可以通过自然语言找房、咨询租赁规则、发起预约和查询租约。第二个是运营侧智能分析助手 AptInsight，它让管理员用自然语言分析预约、租约、房源和租金数据，并通过安全只读 SQL 返回表格、图表与总结。

在这些项目中，我重点关注的不只是模型调用，而是如何让 AI 接入真实业务后仍然可控。例如在 AptGuide 中，房源和租约事实仍由租赁业务后端维护，预约等写操作需要用户确认后才执行；在 AptInsight 中，模型生成的 SQL 必须经过 AST 安全校验，并使用只读数据库权限。

我也会使用 AI Coding 工具提高开发效率，但自己负责需求拆解、系统边界、关键代码理解和验证。希望在后续工作中进一步把 AI 能力与后端工程结合，做稳定、可验证的业务应用。

## 面试优势表达

| 字节关注点 | 可表达内容 |
| --- | --- |
| 逻辑性 | 能将项目按业务目标、架构边界、方案、验证结果和局限性结构化表达 |
| 学习能力 | 从传统租赁业务后端延伸到 RAG、Agent、Text-to-SQL 与 eval |
| 工程意识 | 不把 Prompt 当硬约束；将确认、权限、安全校验放在系统层 |
| 真实性 | 能明确区分已实现、已验证、设计考虑和后续方向 |
| 沟通能力 | 能将 AI 技术解释为解决业务问题的流程，而不是只堆技术词 |

## 表达边界

| 可以说 | 不要说 |
| --- | --- |
| 独立服务和关键链路已经开发验证 | 已生产上线、已承载真实大规模用户 |
| 做过 live eval、测试与问题分析 | 所有指标已经达到生产标准 |
| 设计并实现了确认式操作/SQL Guard 等安全措施 | 曾处理不存在的线上安全事故 |
| 使用 AI Coding 辅助开发并负责审查验收 | AI 代替自己完成了全部设计与代码 |
