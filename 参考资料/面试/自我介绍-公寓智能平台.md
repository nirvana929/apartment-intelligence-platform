## 2 分钟版本

面试官您好，我叫吴超文，目前是中山大学计算机科学与技术专业硕士，研究方向是嵌入式实时系统、操作系统和任务调度。本科是重庆邮电大学计算机科学与技术专业，GPA 3.57/4.0，专业前 2%。我目前主要关注 Java 后端开发和大模型应用开发，比较希望做能把后端工程能力和 AI 应用落地结合起来的工作。

我的核心项目是 Apartment Intelligence Platform，一个围绕公寓租赁业务构建的平台。它包含三个主要部分：第一个是 SmartLease 租赁业务管理系统，第二个是租客侧 AI 助手 AptGuide，第三个是运营侧 AI 分析助手 AptInsight。

SmartLease 是整个系统的业务底座，基于 Spring Boot、MyBatis-Plus、MySQL、Redis、JWT、MinIO 和 Nginx 实现。我在里面完成了公寓、房间、预约、租约、用户等核心模块的业务建模、落库设计、多条件查询、分页接口和状态流转约束。前端有租客 H5 和运营管理后台两个入口，请求先经过 Nginx 反向代理进入后端服务，再由 Controller 层分发到租客端接口、管理端接口或者 AI 转发接口。

在这个业务底座之上，我把 AI 能力拆成两个独立服务。AptGuide 是面向租客的 C 端 Agent，解决找房、租房规则咨询、预约看房和租约查询等场景。它通过 LLM-first 结构化理解解析用户需求，再结合 RAG、Milvus 语义召回、业务房源校验和工具调用完成推荐和预约流程。为了避免 AI 直接写业务数据，预约创建、取消和偏好记忆写入都通过 pending action 待确认机制完成。

AptInsight 是面向运营人员的 B 端分析 Agent，解决临时数据分析需求。运营人员可以用自然语言询问预约量、租约状态、租金分布、浏览热度等问题，系统用 LangGraph 编排意图识别、SQL 生成、SQL Guard、只读执行、图表构建和答案总结。这里我重点做了基于 sqlglot AST 的 SQL Guard，只允许 SELECT，拦截多语句、危险操作、非白名单表字段和高敏字段，并配合只读 MySQL 账号降低风险。

工程上，我也做了自动化评测。AptInsight 构建了 Agent Eval Harness，覆盖 40 个业务分析、安全测试和边界拒答场景，正式评测 35/40 通过，整体通过率 87.5%，安全用例 6/6 通过。AptGuide 也做了单测、Live RAG 集成测试和前端 E2E 阶段性验证。开发过程中，我会使用 Codex 和 Claude Code 辅助做计划拆解、实现和评测迭代，但系统架构、业务边界、安全策略和验收标准是我自己主导设计的。

如果后续展开，我可以重点讲三个方向：SmartLease 的业务建模和后端接口设计，AptGuide 的 RAG 加工具调用链路，或者 AptInsight 的 Text-to-SQL、安全治理和 Agent Eval。

## 3 分钟技术引导版本

面试官您好，我叫吴超文，目前是中山大学计算机科学与技术专业硕士，研究方向是嵌入式实时系统、操作系统和任务调度。本科毕业于重庆邮电大学计算机科学与技术专业，GPA 3.57/4.0，专业前 2%。我目前的求职方向是 AI 应用开发和 Java 后端开发，希望把后端工程能力和大模型应用落地结合起来。

我最近主要做了一个公寓租赁智能平台，整体叫 Apartment Intelligence Platform。这个项目的主线是：先搭一个真实的租赁业务系统，再在这个业务系统上扩展两个不同角色的 AI Agent。

第一部分是 SmartLease，它是整个系统的业务底座。我用 Spring Boot、MyBatis-Plus、MySQL、Redis、JWT、MinIO 和 Nginx 实现了公寓租赁管理后端，覆盖公寓、房间、预约、租约、用户等核心模块。这里我主要负责业务建模、表结构设计、RESTful 接口、多条件查询、分页检索、租约状态流转和缓存设计。Redis 主要用于热点房源缓存和 Token 管理，MinIO 用于图片资源，Nginx 用于静态资源代理和反向代理。

第二部分是系统接入架构。前端有两个入口：租客 H5 和运营管理后台。请求先通过 Nginx 反向代理进入后端，再由 Spring Boot Controller 层分发到对应接口。对于 AI 能力，我没有把模型调用直接塞进 Java 单体，而是把 AptGuide 和 AptInsight 抽象成两个独立的 Python FastAPI 服务，分别监听不同端口。Java 后端通过 Controller 层或内部工具接口调用这两个服务。这样设计的好处是边界清楚：Java 后端负责业务事实、权限和数据一致性，Python AI 服务负责自然语言理解、Agent 编排和模型调用。

第三部分是 AptGuide，它是面向租客的 C 端智能找房助手。它支持自然语言找房、租房规则问答、预约看房和租约查询。技术上，我采用 LLM-first 结构化理解，把用户输入解析成任务类型、硬性条件、软偏好、检索查询和风险等级；如果模型输出低置信度或字段矛盾，就进入澄清流程。RAG 部分使用 Milvus 做语义召回，再结合业务后端校验、加权排序和置信度门控返回房源推荐。预约这类写操作不会直接执行，而是先生成待确认动作，用户确认后才调用后端工具接口。

第四部分是 AptInsight，它是面向运营人员的 B 端智能分析助手。运营人员可以问“本月各公寓预约量排名”“有效租约数量”“租金分布”“浏览热度”等问题。系统通过 LangGraph 把 Text-to-SQL 链路拆成意图识别、SQL 生成、安全校验、只读执行、图表构建和答案总结几个节点。SQL 生成后不会直接执行，而是进入基于 sqlglot 的 AST 级 SQL Guard，检查是否为单条 SELECT、是否访问白名单表和字段、是否包含危险操作或高敏字段。通过后才交给只读 MySQL 执行器，最后返回表格、图表和运营总结。

这个项目我比较重视评测和安全。AptInsight 有 Agent Eval Harness，相当于一套自动化评测脚手架，包含 YAML 测试集、runner、trace 输出、grader 和报告。正式报告执行了 40 条业务、安全和边界用例，35 条通过，整体通过率 87.5%；安全类 6 条全部通过，包括 DELETE、UPDATE、DROP、敏感字段和执行 SQL 等场景。失败用例我也做了归因，主要是意图识别过保守、复杂 SQL 生成不稳定和 grader 规则偏窄，不是 SQL Guard 安全边界失效。

这个项目里我想重点体现两点能力：第一，我不是只会调用模型，而是能把 AI Agent 接入真实业务系统，并明确业务事实、权限和写操作边界；第二，我不是只做 demo，而是通过 SQL Guard、pending action、只读账号、结构化校验和 Agent Eval 把 AI 系统做得可控、可测、可复盘。

```text
租客 H5 / 运营后台
  ↓
Nginx 反向代理
  ↓
Spring Boot SmartLease
  ├─ 租客端接口：找房、预约、租约、个人中心
  ├─ 管理端接口：公寓、房间、预约、租约、用户管理
  ├─ AI 转发 / 内部工具接口
  │    ├─ AptGuide FastAPI：租客侧 Agent，RAG + Tool Calling

  ↓
MySQL / Redis / MinIO / Milvus
```

## 需要避免的说法

- 不要说“AI 直接操作数据库”。更准确是：AptGuide 通过 lease 内部工具接口访问业务事实，AptInsight 使用只读 MySQL 查询分析数据。
- 不要说“AptInsight 可以回答所有经营问题”。更准确是：它只能回答 schema 和指标口径覆盖范围内的问题，超出范围要拒答或说明限制。
- 不要说“代码都是 AI 写的”。更准确是：核心架构、业务边界、安全策略和验收标准由我主导，Codex / Claude Code 用于计划拆解、代码实现辅助和评测迭代。
- 不要把 87.5% 说成“准确率绝对可靠”。更准确是：40 条正式 harness 中 35 条通过，是一个可解释的阶段性回归基线，安全用例 6/6 通过。
