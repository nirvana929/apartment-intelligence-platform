## AptGuide 3.0 - 租客端智能找房助手

### 项目定位

AptGuide 3.0 是面向租客 C 端的智能找房助手，服务找房、租房规则咨询、预约看房、租约查询、偏好记忆和人工转接等场景。它不是单纯聊天机器人，而是一个接入租赁业务系统的 AI Agent 服务。

最终系统链路：

```text
rentHouseH5
  -> lease web-app /app/ai/chat
      -> AptGuide 3.0 /api/chat
          -> lease internal tools
          -> Milvus
          -> MySQL / Redis
          -> LLM
```

### 技术栈

- Python、FastAPI
- LLM Structured Output
- RAG、Milvus、Embedding
- MySQL、Redis、SQLAlchemy
- Vue3、Playwright
- LangSmith tracing 可选

### 核心能力

- LLM-first 结构化理解：由模型将自然语言解析为任务、硬性条件、软偏好、检索查询、风险等级和置信度。
- 澄清机制：当模型输出低置信度、JSON 解析失败、字段矛盾或用户表达模糊时，不用关键词硬猜，而是进入澄清流程。
- 7 类业务流程：clarify、room_search、kb_qa、appointment、lease、memory、handoff。
- RAG 检索链路：多查询向量召回、房源业务校验、五维加权排序、知识库重排、置信度门控和检索诊断。
- 写操作确认：预约创建、预约取消、记忆写入等操作先生成 pending action，用户确认后才真正调用业务接口或写入状态。
- 状态持久化：使用 MySQL 保存会话、消息、待确认动作、记忆、人工转接、Trace、Procedure Run 和审计事件；Redis 管理会话和待确认动作 TTL 热状态。
- 系统边界清晰：AptGuide 3.0 保存 Agent 状态，lease 系统仍然是用户、房源、预约、租约和合同等业务事实的来源。

### 个人负责内容

- 设计 AptGuide 3.0 的整体 Agent 架构和请求链路。
- 设计 LLM-first 结构化理解契约，避免关键词路由和规则兜底带来的误判。
- 实现业务 Procedure Runtime，把找房、问答、预约、租约、记忆、人工转接等流程拆成可测试的 typed procedures。
- 实现 RAG 检索、排序和置信度门控，确保推荐结果经过业务后端校验。
- 设计 MySQL + Redis 的 Agent 状态管理方案，支持待确认动作、会话、记忆和审计。
- 补充前端验证页面和 Playwright E2E，用于演示和端到端验证。

### 可量化或可验证成果

- 阶段性验证覆盖单元测试、Live RAG 集成测试、前端 E2E 和依赖健康检查。

### 面试可讲点

1. 为什么不用关键词路由？
   - 关键词规则容易误判，例如“我不想预约了”不能简单看到“预约”就执行预约流程。
   - AptGuide 3.0 采用模型结构化输出 + 契约校验 + 低置信度澄清。

2. 写操作为什么要二次确认？
   - LLM 可能理解错用户意图，不能直接创建/取消预约或写入长期偏好。
   - pending action 能把“识别意图”和“真正执行写操作”隔离开。

3. 记忆功能怎么做？
   - 用户表达长期偏好后，系统提取记忆候选。
   - 生成待确认动作。
   - 用户确认后写入 memory repository。
   - 后续找房时合并当前需求和历史偏好，影响检索与排序。

4. RAG 检索为什么要经过 lease 校验？
   - 向量召回只代表语义相关，不代表房源真实可用。
   - 房源状态、预约、租约等业务事实必须由 lease 后端校验。

5. 房源推荐为什么部分指标可能 N/A？
   - 开放式推荐没有唯一正确 room_id。
   - 如果没有人工标注候选集，Hit@K、MRR、nDCG 这类指标不能稳定计算。

## AptInsight - 公寓运营智能分析助手

### 项目定位

AptInsight 是面向公寓后台运营人员的智能数据分析助手。它支持运营人员用自然语言提问，系统自动完成意图识别、SQL 生成、安全校验、只读查询、表格/图表生成和运营总结。

核心链路：

```text
运营人员自然语言问题
  -> Agent 理解问题
  -> 生成只读 SQL
  -> SQL Guard 安全校验
  -> MySQL 查询
  -> 返回表格、图表和运营总结
```

### 技术栈

- Python、FastAPI
- LangGraph
- MySQL、SQLAlchemy、asyncmy
- sqlglot
- Pydantic、pydantic-settings
- Qwen / OpenAI-compatible LLM
- Redis、JSON logs、trace_id

### 核心能力

- Text-to-SQL：将预约、租约、房源、租金、浏览热度等运营问题转换为 SQL。
- LangGraph 工作流：拆分意图识别、SQL 生成、SQL 安全校验、查询执行、图表构建和答案总结。
- SQL Guard：基于 sqlglot 做 AST 级校验，只允许 SELECT，拦截多语句、系统库、敏感字段、非白名单表/字段。
- 只读数据库策略：使用只读 MySQL 账号，即使模型生成错误 SQL，也不能破坏业务库。
- Schema / 指标 / few-shot：约束模型正确使用业务表、字段、枚举、时间范围和逻辑删除条件。
- Agent Eval Harness：固定评测集，回归业务分析、安全测试、边界拒答和指标口径。

### 个人负责内容

- 设计并实现 AptInsight 独立 FastAPI Agent 服务。
- 设计 LangGraph Text-to-SQL 工作流。
- 实现 SQL Guard、数据脱敏和表字段白名单策略。
- 整理数据库 Schema、指标口径和 few-shot 示例。
- 构建 Agent Eval Harness，并根据评测结果迭代提示词和验证规则。
- 对多模型链路进行质量与耗时评估，优化提示词、结构化输出和 token 配置。

### 可量化或可验证成果

- Agent Eval Harness 覆盖 40 个测试场景。
- 最终评测通过率 87.5%。
- 安全用例通过率 100%。
- 核心指标口径通过率 100%。
- 单元测试 22 项通过，Ruff Lint 0 错误。
- 典型意图识别、SQL 生成、答案总结链路耗时控制在约 5s。

### 面试可讲点

1. 为什么用 LangGraph？
   - Text-to-SQL 不是一次模型调用，有意图识别、安全校验、空结果、拒答、SQL 执行异常等分支。
   - LangGraph 能把 Agent 变成可观测、可测试、可回归的状态机。

2. 为什么 SQL Guard 用 sqlglot？
   - 正则容易被绕过，AST 能更准确识别语句类型、表、字段、子查询和多语句风险。

3. 如何防止模型乱查敏感数据？
   - 只读账号 + AST 校验 + 表字段白名单 + 敏感字段拦截 + 结果脱敏。

4. 为什么需要 Agent Eval Harness？
   - Prompt、Schema、few-shot 一改就可能影响 SQL 生成。
   - 安全类用例必须 100% 回归，不能靠人工试问。

5. 哪些问题不能回答？
   - 当前数据库没有支付流水时，不能声称“实际收款”。
   - 预约表没有 room_id 时，不能直接分析“预约量最高的房间”。

## SmartLease - 租赁业务管理平台

### 项目定位

SmartLease 是面向公寓运营的租赁业务管理平台，覆盖房源管理、预约看房、签约、续约、退租、图片上传、缓存和部署等后端能力。它是简历中证明 Java 后端基本盘的项目。

### 技术栈

- Java、SpringBoot
- MyBatis-Plus、MySQL
- Redis、JWT
- MinIO、Nginx
- Linux 部署

### 核心能力

- 租赁业务建模：公寓、房间、租约、预约等实体关系设计。
- 多条件查询：支持后台多维度条件检索和分页。
- 状态流转：签约、续约、退租等流程在接口层做状态约束。
- 缓存与登录态：使用 Redis 做热点房源缓存和 Token 管理。
- 文件存储：集成 MinIO 支持房源图片上传。
- 部署：使用 Nginx 做静态资源代理和反向代理，在 Linux 环境部署。

### 个人负责内容

- 负责核心业务建模和数据库落库设计。
- 设计并实现房源、预约、租约等核心接口。
- 设计租约状态流转和接口层状态校验。
- 接入 Redis、JWT、MinIO、Nginx，完成基础工程闭环。

### 面试可讲点

1. 租约状态如何设计？
   - 不同接口只能在合法状态下执行，例如未签约不能退租，已退租不能续约。

2. 为什么要用 Redis？
   - 热点房源减少重复查询。
   - Token 管理支撑登录态校验。

3. MinIO 用来解决什么？
   - 房源图片和静态资源不直接塞进数据库，通过对象存储管理。

4. 这个项目和 AI 项目的关系？
   - SmartLease 提供租赁业务基础，AptInsight 和 AptGuide 是在租赁业务系统之上的 AI 能力扩展。
