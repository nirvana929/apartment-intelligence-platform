# AptInsight 系统集成实施文档

> 面向后续执行代码集成的 agent。本文只定义集成边界、接口契约、文件改动清单、实施顺序和验收方式，不在本文档中直接修改业务代码。

## 1. 集成目标

AptInsight 是面向后台管理员的智能运营分析助手，应集成到现有管理后台中，作为后台运营人员查询公寓、房间、预约、租约等经营数据的分析入口。

集成后的调用链固定为：

```text
rentHouseAdmin 管理后台
  -> lease/web-admin Spring Boot 后台接口
  -> AptInsight FastAPI Agent 服务
  -> 只读 MySQL 查询
```

核心原则：

1. 前端只调用 `lease/web-admin` 的 `/admin/**` 接口，不直接调用 Python Agent。
2. Spring Boot 复用现有后台登录鉴权、统一响应结构和异常处理。
3. AptInsight 保持独立 FastAPI 服务，只通过内部网络被 Spring Boot 调用。
4. 新增接口使用 `/admin/ai/**` 命名空间，不改动现有 `/admin/apartment/**`、`/admin/room/**`、`/admin/agreement/**` 等业务接口。
5. 移动端或 H5 项目 `rentHouseH5` 不在本次集成范围内。

## 2. 当前系统判断

### 2.1 仓库项目边界

```text
.
├── AptInsight/       # Python FastAPI + LangGraph Text-to-SQL 智能分析助手
├── lease/            # Spring Boot 租赁业务后端
├── rentHouseAdmin/   # Vue3 管理后台前端
└── rentHouseH5/      # H5/移动端前端，本次不接入 AptInsight
```

本次只涉及三个项目：

| 项目 | 角色 | 本次职责 |
| --- | --- | --- |
| `AptInsight` | Python Agent 服务 | 提供自然语言分析能力，执行只读 SQL，返回答案、表格、图表配置 |
| `lease/web/web-admin` | 后台业务网关 | 新增 `/admin/ai/chat` 包装接口，转发到 AptInsight |
| `rentHouseAdmin` | 管理后台 UI | 新增智能运营分析页面、路由和 API 调用 |

## 3. 推荐架构

### 3.1 为什么不让前端直连 AptInsight

不推荐：

```text
rentHouseAdmin -> AptInsight
```

原因：

1. AptInsight 当前没有后台 JWT 鉴权。
2. 浏览器直连会带来 CORS、服务暴露和 token 传递问题。
3. 前端现有错误处理只适配 Spring Boot 的 `Result<T>`。
4. 以后做查询审计、用户维度限流、权限控制时，Spring Boot 是更合适的边界。

推荐：

```text
rentHouseAdmin -> /admin/ai/chat -> AptInsight /api/chat
```

Spring Boot 包装层职责：

1. 复用 `/admin/**` 登录鉴权。
2. 把前端 camelCase 请求转换为 AptInsight snake_case 请求。
3. 把 AptInsight snake_case 响应转换为前端更好用的 camelCase 响应。
4. 把结果包进 `Result.ok(data)`。
5. 处理超时、网络错误和 Agent 错误。
6. 可选记录查询日志。

Spring Boot 不做的事：

1. 不生成 SQL。
2. 不调用大模型。
3. 不执行 Agent 生成的 SQL。
4. 不把 Python 原始错误堆栈透传给前端。

### 3.2 服务部署边界

开发环境建议：

```text
rentHouseAdmin: http://localhost:5173
lease web-admin: http://127.0.0.1:8080
AptInsight: http://127.0.0.1:8000
MySQL: 127.0.0.1:3306 或 192.168.211.128:3306
Redis: 127.0.0.1:6379
```

生产或演示环境建议：

```text
浏览器
  -> Nginx / 前端静态资源
  -> lease web-admin:8080
  -> AptInsight:8000 仅内网可访问
  -> MySQL 只读账号
```

AptInsight 不应直接暴露公网。如果必须临时暴露，需要单独增加服务级鉴权或网关白名单。

## 4. 接口契约

### 4.1 前端调用 Spring Boot

新增接口：

```http
POST /admin/ai/chat
Content-Type: application/json
access-token: <后台 JWT>
```

请求体：

```json
{
  "sessionId": "aptinsight-1714630000000",
  "question": "最近 30 天各公寓预约量排名",
  "needChart": true,
  "exposeSql": true,
  "maxRows": 100
}
```

字段说明：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `sessionId` | string | 否 | 前端生成 | 当前会话 ID |
| `question` | string | 是 | 无 | 用户问题，前端限制 500 字以内 |
| `needChart` | boolean | 否 | `true` | 预留字段。当前 AptInsight 会由 Agent 自行判断是否返回图表 |
| `exposeSql` | boolean | 否 | 开发 true，生产 false | 是否向前端展示 SQL。当前 AptInsight 配置项为 `EXPOSE_SQL` |
| `maxRows` | number | 否 | 100 | 预留字段。当前 AptInsight 执行节点默认最多返回 100 行 |

成功响应：

```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "traceId": "7b7a4b2e-...",
    "sessionId": "aptinsight-1714630000000",
    "answer": "最近 30 天预约量最高的是回龙观社区。",
    "summary": "预约量集中在头部公寓。",
    "rows": [
      {
        "apartment_name": "回龙观社区",
        "appointment_count": 8
      }
    ],
    "columns": [
      {
        "key": "apartment_name",
        "title": "apartment_name",
        "type": "string"
      },
      {
        "key": "appointment_count",
        "title": "appointment_count",
        "type": "number"
      }
    ],
    "chart": {
      "type": "bar",
      "option": {}
    },
    "sql": "SELECT ...",
    "warnings": [],
    "error": null,
    "execution": {
      "durationMs": 1280.55,
      "rowCount": 1,
      "truncated": false
    }
  }
}
```

Agent 逻辑失败但 HTTP 正常时，仍返回 `code=200`，在 `data.error` 中带错误信息。这样前端可以保留同一个结果面板，展示“未能完成分析”的状态。

网络失败、超时、Python 服务不可用时，Spring Boot 返回：

```json
{
  "code": 203,
  "message": "智能分析服务暂时不可用，请稍后重试",
  "data": null
}
```

Spring Boot 内部调用：

```http

Content-Type: application/json
```

请求体：

```json
{
  "question": "最近 30 天各公寓预约量排名",

}
```

健康检查：

```http

```

```json

```

### 4.3 字段转换规则

| AptInsight 字段 | Spring/前端字段 | 说明 |
| --- | --- | --- |
| `trace_id` | `traceId` | 链路追踪 ID |
| `session_id` | `sessionId` | 当前 Python 响应不返回该字段，Spring 可用请求值补齐 |
| `processing_time_ms` | `execution.durationMs` | 总耗时 |
| `rows` | `rows` | 保持对象数组 |
| `columns[].name` | `columns[].key` | 表格列 key |
| `columns[].name` | `columns[].title` | 第一版可直接使用字段名，后续再做中文映射 |
| `columns[].type` | `columns[].type` | 类型透传，缺省为 `string` |
| `chart.type` | `chart.type` | ECharts 图表类型 |
| `chart.option` | `chart.option` | ECharts option |
| `sql` | `sql` | 生产环境可由 Spring 根据配置置空 |
| `warnings` | `warnings` | 警告列表 |
| `error` | `error` | Agent 内部可恢复错误 |

### 5.2 配置项

在 `application.yml` 增加：

```yaml
aptinsight:
  base-url: ${APTINSIGHT_BASE_URL:http://127.0.0.1:8000}
  connect-timeout-ms: ${APTINSIGHT_CONNECT_TIMEOUT_MS:3000}
  read-timeout-ms: ${APTINSIGHT_READ_TIMEOUT_MS:45000}
```

说明：

### 5.4 HTTP Client

当前项目使用 Spring Boot 3.0.5，已有 `spring-boot-starter-web`，可以用 `RestTemplate`，避免新增 WebFlux 依赖。

建议：

1. 在 `AptInsightClientConfiguration` 中通过 `RestTemplateBuilder` 创建专用 `RestTemplate`。
2. 设置 connect timeout 和 read timeout。
3. 在 `AptInsightClient` 中封装 `health()` 和 `chat()`。
4. 捕获 `ResourceAccessException`、`HttpStatusCodeException` 和通用异常，转成业务异常。

错误处理建议：

| 场景 | Spring 行为 | 前端表现 |
| --- | --- | --- |
| Python 返回 200 且 `error=null` | `Result.ok(data)` | 展示答案、表格、图表 |
| Python 返回 200 且 `error` 有值 | `Result.ok(data)` | 在结果面板展示错误和可用的部分结果 |
| Python HTTP 500 | `Result.fail(203, "智能分析服务处理失败")` | 消息提示 |
| Python 连接失败 | `Result.fail(203, "智能分析服务暂时不可用，请稍后重试")` | 消息提示 |
| Python 超时 | `Result.fail(203, "智能分析服务响应超时，请缩小查询范围后重试")` | 消息提示 |

### 5.5 Controller

新增：

```java
@RestController
@RequestMapping("/admin/ai")
public class AptInsightController {
    @PostMapping("/chat")
    public Result<AptInsightChatResponse> chat(@RequestBody AptInsightChatRequest request) {
        return Result.ok(aptInsightService.chat(request));
    }
}
```

校验要求：

1. `question` 不能为空。
2. `question` 长度不超过 500。
3. `sessionId` 为空时，Spring 可生成一个 `ai-` 前缀 ID，也可以由前端生成。

### 5.6 可选查询日志

第一版集成不强制新增数据库表，避免影响现有系统。上线后如需审计，再新增 `ai_query_log`。

建议表结构：

```sql
CREATE TABLE ai_query_log (
  id BIGINT NOT NULL AUTO_INCREMENT,
  trace_id VARCHAR(64) NOT NULL,
  session_id VARCHAR(64) DEFAULT NULL,
  user_id BIGINT DEFAULT NULL,
  question VARCHAR(500) NOT NULL,
  generated_sql TEXT,

  row_count INT DEFAULT NULL,
```

日志只保存问题、SQL、状态、耗时和行数，不保存完整 `rows`。

2. 提交按钮：loading 时禁用，避免重复提交。
3. 示例问题：提供 4-6 个后台运营常用问题，点击后填入输入框。
4. 结果摘要：展示 `answer` 和 `summary`。
5. 表格结果：使用 Element Plus `el-table` 渲染 `columns` 和 `rows`。
6. 图表结果：如果 `chart.option` 存在，使用已有 `vue-echarts` 或 `echarts` 渲染。
7. SQL 折叠区：仅当响应中 `sql` 非空时展示，默认折叠。
8. 警告和错误：展示 `warnings` 和 `error`，但不让页面崩溃。
9. trace 信息：展示 `traceId`、耗时、行数，便于排查问题。

建议示例问题：

```text
最近 30 天各公寓预约量排名
本月租约状态分布
当前已发布房间数量是多少
各城区公寓数量对比
最近 6 个月每月新增租约趋势
租金最高的 10 个房间
```

页面风格要求：

1. 保持后台工具页风格，不做营销式首页。
2. 使用 Element Plus 现有表单、按钮、表格、折叠面板。
3. 页面入口作为一个普通后台菜单项，不影响首页、用户管理、公寓管理、租约管理等现有菜单。
4. 图表和表格可以用 tabs 切换，也可以上下排列；第一版优先稳定可用。

## 7. AptInsight 服务配置要求

### 7.1 数据库配置必须与 lease 对齐

当前存在一个需要执行 agent 特别核对的差异：

| 位置 | 当前默认库名 |
| --- | --- |
| `lease/web/web-admin/src/main/resources/application.yml` | `lease` |
| `AptInsight/.env.example` | `least` |

执行集成前必须确认实际 MySQL 数据库名。AptInsight 和 `lease/web-admin` 必须连接同一套业务表，否则前端看到的业务数据与智能分析结果会不一致。

建议：

```env
MYSQL_DATABASE=lease
```

如果实际环境数据库名就是 `least`，则 Java 的 `MYSQL_URL` 也必须指向 `least`。

### 7.2 AptInsight 生产建议

`.env` 建议：

```env
APP_ENV=prod
LOG_LEVEL=INFO
LLM_TIMEOUT_SECONDS=30
MYSQL_QUERY_TIMEOUT_SECONDS=10
MYSQL_MAX_ROWS=100
EXPOSE_SQL=false
ENABLE_QUERY_LOG=true
```

数据库账号建议：

1. 使用只读账号。
2. 只授予 AptInsight 白名单表的 `SELECT` 权限。
3. 不复用 Java 后端的写库账号。

服务启动：

```bash
cd AptInsight
uv sync
uv run uvicorn aptinsight.main:app --host 127.0.0.1 --port 8000
```

如果 Spring Boot 和 AptInsight 不在同一台机器，`--host` 应绑定内网地址，并在安全组或防火墙中只允许 Spring Boot 访问。

## 10. 风险和处理

| 风险 | 表现 | 处理 |
| --- | --- | --- |
| 数据库名不一致 | 后台列表和 AI 分析结果不一致 | 统一 Java `MYSQL_URL` 和 AptInsight `MYSQL_DATABASE` |
| Python 接口路径用错 | Spring 调用 404 | 使用当前真实路径 `/api/chat` 和 `/health` |
| 前端超时过短 | LLM 查询还没结束前端已报错 | `chatWithAptInsight` 单独设置 `timeout: 60000` |
| Python 服务暴露公网 | 未鉴权访问 Agent | AptInsight 仅内网访问，前端只走 `/admin/ai/chat` |
| SQL 泄露 | 普通管理员看到生成 SQL | 生产设置 `APTINSIGHT_EXPOSE_SQL=false` 或前端按权限隐藏 |
| Agent 返回 snake_case | 前端字段读不到 | Spring 层统一转换为 camelCase |
| 图表 option 不兼容 | 图表空白 | 前端检测 `chart?.option`，失败时降级展示表格 |
| 影响原后台接口 | 旧功能异常 | 新增 `/admin/ai/**`，不修改现有接口和 axios 全局行为 |

## 11. 不纳入第一版的事项

第一版不做以下内容，避免集成范围过大：

1. 不做多轮追问上下文记忆，只保留 `sessionId` 字段。
2. 不做复杂权限到表级字段级的后台用户授权，先依赖 AptInsight 白名单和只读账号。
3. 不新增管理后台动态菜单权限体系，先使用静态路由。
4. 不把 AptInsight 合并进 Spring Boot 进程。
5. 不让 `rentHouseH5` 接入 AptInsight。
6. 不新增大规模数据库迁移；查询日志表作为后续审计增强。

## 12. 给执行 agent 的最终指令

执行集成时按以下约束操作：

1. 先完成 Spring Boot 包装接口，再做前端页面。
2. 不改 AptInsight 的核心 Agent 流程，除非接口契约测试证明必须修复。
3. 不改现有后台业务接口路径和响应结构。
4. 不改全局 axios 超时，智能分析 API 单独设置超时。
5. 不升级项目主依赖。
6. 每完成一层就运行对应测试或手动 curl 验证。
7. 如果发现 `lease` 和 `AptInsight` 连接的数据库不是同一个，先停止集成并统一配置。
