# AptInsight 数据库字典与指标口径

## 1. 数据库说明

当前后端 `application.yml` 连接 MySQL：

```text
host: 192.168.211.128
port: 3306
database: least
```

项目中的 SQL dump 文件 `hello-minio/lease.sql` 显示库名为 `lease`。实际实现时以运行环境数据库为准，AptInsight 文档只约束业务表和字段。

## 2. 通用字段

多数业务表继承 `BaseEntity`，包含：

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `id` | 主键 | 自增 |
| `create_time` | 创建时间 | 可用于新增趋势统计 |
| `update_time` | 更新时间 | 用于最近变更 |
| `is_deleted` | 逻辑删除 | 默认 `0` 表示未删除，查询必须过滤 |

所有业务 SQL 默认添加：

```sql
is_deleted = 0
```

## 3. 核心业务表

### 3.1 `apartment_info` 公寓信息表

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `id` | 公寓 ID | 主键 |
| `name` | 公寓名称 | 展示名称 |
| `introduction` | 公寓介绍 | 长文本，分析中少用 |
| `province_id` | 省份 ID | 地区筛选 |
| `province_name` | 省份名称 | 可直接展示 |
| `city_id` | 城市 ID | 地区筛选 |
| `city_name` | 城市名称 | 可直接展示 |
| `district_id` | 区县 ID | 地区筛选 |
| `district_name` | 区县名称 | 可直接展示 |
| `address_detail` | 详细地址 | 可用于定位 |
| `latitude` | 经度 | 当前字段注释为经度 |
| `longitude` | 纬度 | 当前字段注释为纬度 |
| `phone` | 公寓前台电话 | 敏感，默认不返回 |
| `is_release` | 是否发布 | 1 已发布，0 未发布 |

常用关联：

```text
apartment_info.id = room_info.apartment_id
apartment_info.id = view_appointment.apartment_id
apartment_info.id = lease_agreement.apartment_id
```

### 3.2 `room_info` 房间信息表

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `id` | 房间 ID | 主键 |
| `room_number` | 房间号 | 展示名称 |
| `rent` | 租金，元/月 | 可用于租金分析 |
| `apartment_id` | 所属公寓 ID | 关联公寓 |
| `is_release` | 是否发布 | 1 已发布，0 未发布 |

常用关联：

```text
room_info.apartment_id = apartment_info.id
room_info.id = lease_agreement.room_id
room_info.id = browsing_history.room_id
```

注意：当前预约表没有 `room_id`，不能直接统计房间预约量。

### 3.3 `view_appointment` 预约看房信息表

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `id` | 预约 ID | 主键 |
| `user_id` | 用户 ID | 关联用户 |
| `name` | 用户姓名 | 默认不用于展示明细 |
| `phone` | 用户手机号 | 敏感，默认脱敏 |
| `apartment_id` | 预约公寓 ID | 当前只到公寓维度 |
| `appointment_time` | 预约时间 | 预约趋势核心字段 |
| `additional_info` | 备注 | 默认不分析 |
| `appointment_status` | 预约状态 | 1 待看房，2 已取消，3 已看房 |

常用指标：

```text
预约量 = COUNT(view_appointment.id)
待看房量 = appointment_status = 1
取消量 = appointment_status = 2
已看房量 = appointment_status = 3
```

### 3.4 `lease_agreement` 租约信息表

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `id` | 租约 ID | 主键 |
| `phone` | 承租人手机号 | 敏感，默认脱敏 |
| `name` | 承租人姓名 | 默认不展示明细 |
| `identification_number` | 身份证号 | 严禁返回 |
| `apartment_id` | 签约公寓 ID | 关联公寓 |
| `room_id` | 签约房间 ID | 关联房间 |
| `lease_start_date` | 租约开始日期 | 有效租约判断 |
| `lease_end_date` | 租约结束日期 | 有效租约判断 |
| `lease_term_id` | 租期 ID | 关联租期 |
| `rent` | 租金，元/月 | 合同租金 |
| `deposit` | 押金 | 押金分析 |
| `payment_type_id` | 支付类型 ID | 关联支付方式 |
| `status` | 租约状态 | 见枚举 |
| `source_type` | 租约来源 | 1 新签，2 续约 |
| `additional_info` | 备注 | 默认不分析 |

常用指标：

```text
签约量 = COUNT(status = 2)
有效租约 = status = 2 AND CURDATE() BETWEEN lease_start_date AND lease_end_date
退租量 = COUNT(status = 6)
续约待确认量 = COUNT(status = 7)
合同月租金规模 = SUM(rent) WHERE status = 2
```

### 3.5 `browsing_history` 浏览历史表

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `id` | 浏览记录 ID | 主键 |
| `user_id` | 用户 ID | 可统计用户行为 |
| `room_id` | 浏览房间 ID | 关联房间 |
| `browse_time` | 浏览时间 | 趋势和热度分析 |

常用指标：

```text
浏览量 = COUNT(browsing_history.id)
独立浏览用户数 = COUNT(DISTINCT user_id)
房间热度 = 浏览量 + 预约参考量
```

当前预约只到公寓维度，因此“房间热度”第一版建议只用浏览量和租约状态，不合并预约量。

## 9. 核心指标口径

### 9.1 预约量

定义：

```text
预约量 = view_appointment 中未删除预约记录数量
```

SQL 条件：

```sql
va.is_deleted = 0
```

按状态统计时：

```text
待看房 = appointment_status = 1
已取消 = appointment_status = 2
已看房 = appointment_status = 3
```

### 9.2 看房完成率

定义：

```text
看房完成率 = 已看房预约量 / 总预约量
```

口径：

```text
已看房预约量 = appointment_status = 3
总预约量 = appointment_status in (1,2,3)
```

### 9.3 签约量

定义：

```text
签约量 = lease_agreement 中 status = 2 的租约数量
```

注意：`status = 1` 是签约待确认，不能计入已签约。

### 9.4 有效租约

定义：

```text
有效租约 = 已签约且当前日期位于租约开始和结束日期之间
```

SQL 条件：

```sql
la.status = 2
AND CURDATE() BETWEEN la.lease_start_date AND la.lease_end_date
```

### 9.5 空置房间

定义：

```text
空置房间 = 已发布房间，且当前没有有效租约
```

SQL 逻辑：

```text
room_info.is_release = 1
LEFT JOIN 有效租约
WHERE 有效租约不存在
```

### 9.6 合同月租金规模

定义：

```text
合同月租金规模 = 已签约租约的 rent 合计
```

注意：

1. 这是合同口径。
2. 不是实际收款。
3. 当前库没有账单或支付流水，不能计算真实收入。

### 9.7 平均租金

定义：

```text
平均租金 = AVG(room_info.rent)
```

默认只统计：

```text
已发布、未删除房间
```

### 9.8 浏览量

定义：

```text
浏览量 = browsing_history 中未删除浏览记录数量
```

可按房间、公寓、日期统计。

### 9.9 预约到签约参考转化率

定义：

```text
预约到签约参考转化率 = 同期已签约租约数 / 同期预约数
```

注意：

1. 当前预约和租约没有同一个转化链路 ID。
2. 该指标只能作为公寓维度参考转化率。
3. 不能解释为真实用户从预约到签约的精确转化率。

## 10. 常用 SQL 示例

### 10.1 本月各公寓预约量

```sql
SELECT
  ai.name AS apartment_name,
  COUNT(va.id) AS appointment_count
FROM view_appointment va
JOIN apartment_info ai ON va.apartment_id = ai.id
WHERE va.is_deleted = 0
  AND ai.is_deleted = 0
  AND DATE_FORMAT(va.appointment_time, '%Y-%m') = DATE_FORMAT(CURDATE(), '%Y-%m')
GROUP BY ai.id, ai.name
ORDER BY appointment_count DESC
LIMIT 10;
```

### 10.2 当前有效租约数量

```sql
SELECT
  COUNT(la.id) AS active_agreement_count
FROM lease_agreement la
WHERE la.is_deleted = 0
  AND la.status = 2
  AND CURDATE() BETWEEN la.lease_start_date AND la.lease_end_date;
```

### 10.3 各公寓已签约租约数量

```sql
SELECT
  ai.name AS apartment_name,
  COUNT(la.id) AS signed_agreement_count
FROM lease_agreement la
JOIN apartment_info ai ON la.apartment_id = ai.id
WHERE la.is_deleted = 0
  AND ai.is_deleted = 0
  AND la.status = 2
GROUP BY ai.id, ai.name
ORDER BY signed_agreement_count DESC
LIMIT 10;
```

### 10.4 最近 6 个月新增租约趋势

```sql
SELECT
  DATE_FORMAT(la.create_time, '%Y-%m') AS month,
  COUNT(la.id) AS agreement_count
FROM lease_agreement la
WHERE la.is_deleted = 0
  AND la.create_time >= DATE_SUB(CURDATE(), INTERVAL 6 MONTH)
GROUP BY DATE_FORMAT(la.create_time, '%Y-%m')
ORDER BY month ASC
LIMIT 12;
```

### 10.5 浏览量最高的房间

```sql
SELECT
  ai.name AS apartment_name,
  ri.room_number AS room_number,
  COUNT(bh.id) AS browse_count
FROM browsing_history bh
JOIN room_info ri ON bh.room_id = ri.id
JOIN apartment_info ai ON ri.apartment_id = ai.id
WHERE bh.is_deleted = 0
  AND ri.is_deleted = 0
  AND ai.is_deleted = 0
  AND bh.browse_time >= DATE_SUB(CURDATE(), INTERVAL 30 DAY)
GROUP BY ai.id, ai.name, ri.id, ri.room_number
ORDER BY browse_count DESC
LIMIT 10;
```

### 10.6 预约量高但签约量低的公寓

```sql
SELECT
  ai.name AS apartment_name,
  COUNT(DISTINCT va.id) AS appointment_count,
  COUNT(DISTINCT la.id) AS signed_count,
  ROUND(
    COUNT(DISTINCT la.id) / NULLIF(COUNT(DISTINCT va.id), 0),
    4
  ) AS reference_conversion_rate
FROM apartment_info ai
LEFT JOIN view_appointment va
  ON va.apartment_id = ai.id
  AND va.is_deleted = 0
  AND va.appointment_time >= DATE_SUB(CURDATE(), INTERVAL 30 DAY)
LEFT JOIN lease_agreement la
  ON la.apartment_id = ai.id
  AND la.is_deleted = 0
  AND la.status = 2
  AND la.create_time >= DATE_SUB(CURDATE(), INTERVAL 30 DAY)
WHERE ai.is_deleted = 0
GROUP BY ai.id, ai.name
HAVING appointment_count > 0
ORDER BY appointment_count DESC, reference_conversion_rate ASC
LIMIT 10;
```

## 11. Schema 不支持的分析

| 分析问题 | 当前缺口 | 后续扩展 |
| --- | --- | --- |
| 房间预约量 | `view_appointment` 无 `room_id` | 增加预约房间字段 |
| 真实收款收入 | 无账单/支付流水表 | 增加账单、支付、退款表 |
| 客户转化链路 | 预约和租约无转化关联 ID | 租约保存预约来源 ID |
| 退租原因分析 | 租约状态有退租，但无原因字段 | 增加退租原因 |
| 满意度分析 | 无评价表 | 增加评价和投诉表 |
