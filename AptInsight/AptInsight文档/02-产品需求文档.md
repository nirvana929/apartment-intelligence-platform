# AptInsight 产品需求文档

## 1. 背景

尚庭公寓后台管理系统已经具备完整的业务管理能力，但管理员如果想了解整体运营情况，仍需要在多个页面之间切换，或者手动导出数据再统计。

AptInsight 的目标是提供一个自然语言入口，让管理员直接提问，例如：

```text
最近 30 天预约量趋势怎么样？
各公寓已签约租约数量排名是多少？
哪些已发布房间当前没有有效租约？
```

系统自动返回 SQL、表格、图表和业务总结。

## 2. 用户角色

| 角色 | 使用目标 |
| --- | --- |
| 后台管理员 | 快速查看运营数据、发现异常、辅助管理决策 |
| 运营人员 | 分析预约、签约、空置、租金、浏览热度 |
| 开发者 | 验证 Text-to-SQL、调试 SQL、扩展指标口径 |

第一版默认只面向后台管理员和开发测试者。

## 3. 使用形态

### 3.1 独立测试形态

第一阶段先实现独立形态，便于快速测试 Agent 能力。

入口可以是以下任意一种：

1. FastAPI Swagger 页面。
2. 简单 HTML/Vue 测试页。
3. Postman 或 Apifox。
4. 命令行测试脚本。

该阶段不要求接入现有后台菜单。

### 3.2 后台集成形态

第二阶段在后台管理系统中新增菜单：

```text
智能运营分析
```

页面标题：

```text
AptInsight 智能运营分析助手
```

页面由左侧提问区和右侧结果区组成。

```text
┌──────────────────────┬──────────────────────────┐
│ 对话区                │ 分析结果区                 │
│                      │                          │
│ 推荐问题              │ 运营总结                   │
│ 历史对话              │ SQL 语句                   │
│ 输入框                │ 数据表格                   │
│ 发送按钮              │ 图表                       │
└──────────────────────┴──────────────────────────┘
```

## 4. 核心用户故事

### 4.1 自然语言查询

作为管理员，我希望输入自然语言问题，系统自动查询数据库并返回结果，这样我不需要写 SQL。

验收标准：

1. 输入中文问题后能得到结构化结果。
2. 返回内容包含分析总结、表格和必要图表。
3. 如果生成 SQL，默认可以折叠查看。

### 4.2 查看 SQL

作为开发者或高级管理员，我希望查看系统生成的 SQL，这样可以判断分析结果是否可信。

验收标准：

1. 返回 SQL 语句。
2. SQL 显示在折叠区域，不默认占据主要视线。
3. SQL 必须是只读查询。

### 4.3 图表展示

作为运营人员，我希望系统自动将趋势、排名、占比数据转成图表，这样能更快看出规律。

验收标准：

1. 类别排名优先柱状图。
2. 时间趋势优先折线图。
3. 状态占比优先饼图。
4. 明细列表只展示表格。

### 4.4 经营诊断

作为运营人员，我希望系统不仅给出数据，还能指出异常和建议。

验收标准：

1. 对异常数据有解释。
2. 说明结论依据。
3. 不编造数据库中不存在的信息。
4. 对无法判断的原因使用“可能原因”，不能说成确定事实。

## 5. 功能需求

### 5.1 推荐问题

第一版推荐问题：

```text
本月各公寓预约量排名
最近 30 天预约趋势
当前租约状态占比
各公寓已签约租约数量排名
各区域平均租金
已发布但没有有效租约的房间
最近 30 天浏览量最高的房间
预约量高但签约量低的公寓
```

### 5.2 问答输入

输入限制：

| 项 | 规则 |
| --- | --- |
| 最小长度 | 2 个字符 |
| 最大长度 | 建议 500 个字符 |
| 空输入 | 禁止提交 |
| 危险输入 | 不直接拼 SQL，交给意图识别和安全校验 |

按钮状态：

1. 空输入时发送按钮禁用。
2. 请求中显示加载状态。
3. 请求中可以禁用重复提交。

### 5.3 结果展示

每次回答包含以下区域：

| 区域 | 是否必需 | 说明 |
| --- | --- | --- |
| 业务回答 | 必需 | 用自然语言解释结果 |
| 数据表格 | 必需 | 即使只有一行也展示 |
| SQL 语句 | 建议 | 开发测试阶段必须展示，正式阶段可按权限展示 |
| 图表 | 条件必需 | 数据适合可视化时展示 |
| 警告信息 | 条件必需 | 如结果被截断、字段缺失、无法精确计算 |
| 追问建议 | 可选 | 给出 2 到 3 个相关问题 |

### 5.4 查询历史

第一版可以只保存当前会话历史；第二版再持久化。

历史内容：

1. 提问内容。
2. 回答摘要。
3. SQL。
4. 执行耗时。
5. 成功或失败状态。

### 5.5 错误提示

| 场景 | 用户提示 |
| --- | --- |
| 问题不属于公寓运营分析 | 当前问题不在 AptInsight 支持范围内，请询问公寓、房间、预约、租约、浏览等运营数据 |
| 缺少数据表或字段 | 当前数据库缺少该分析所需字段，无法准确计算 |
| SQL 校验失败 | 生成的查询未通过安全校验，请换一种问法 |
| 查询超时 | 查询耗时过长，请缩小时间范围或增加筛选条件 |
| 无数据 | 当前条件下没有查询到数据 |
| Agent 服务异常 | 智能分析服务暂时不可用，请稍后重试 |

## 6. 支持的问题类型

### 6.1 数据查询类

示例：

```text
查询租金最高的 10 个房间
统计各公寓房间数量
查看本月预约量
```

输出：表格为主，必要时柱状图。

### 6.2 趋势分析类

示例：

```text
最近 30 天预约趋势
最近 6 个月新增租约趋势
```

输出：折线图 + 趋势总结。

### 6.3 占比分析类

示例：

```text
当前租约状态占比
预约状态分布
```

输出：饼图 + 表格。

### 6.4 诊断建议类

示例：

```text
哪些公寓预约量高但签约量低
哪些房间可能存在空置风险
```

输出：表格 + 分析总结 + 建议动作。

### 6.5 指标解释类

示例：

```text
签约率怎么算？
空置房间如何定义？
```

输出：口径解释，不一定执行 SQL。

## 7. 暂不支持的问题类型

| 问题 | 原因 | 推荐提示 |
| --- | --- | --- |
| 真实收款收入 | 当前没有账单和支付流水表 | 可以分析合同月租金规模 |
| 房间预约量 | 预约表没有 `room_id` | 可以分析公寓预约量 |
| 用户画像深度分析 | 用户表字段较少 | 可以分析预约用户数量和浏览行为 |
| 自动修改业务数据 | 安全风险高 | 只支持查询和分析 |
| 外部市场行情 | 当前只连接内部业务库 | 后续可接入外部数据源 |

## 8. 页面交互需求

后台集成阶段页面建议：

### 8.1 左侧对话区

组件：

1. 推荐问题列表。
2. 对话历史。
3. 输入框。
4. 发送按钮。
5. 清空会话按钮。

交互：

1. 点击推荐问题自动填充并发送。
2. Enter 发送，Shift + Enter 换行。
3. 请求中展示加载效果。
4. 失败回答可重试。

### 8.2 右侧结果区

组件：

1. 结果摘要。
2. SQL 折叠面板。
3. 表格。
4. 图表。
5. 警告信息。
6. 查询耗时。

交互：

1. SQL 可复制。
2. 表格支持横向滚动。
3. 图表随容器尺寸自适应。
4. 结果过多时提示已截断。

## 9. 权限需求

第一版独立测试阶段：

1. Agent 使用只读数据库账号。
2. 不暴露到公网。
3. 测试接口可先不接入后台 JWT，但需要本地访问限制或简单 token。

第二版集成阶段：

1. 前端请求 Spring Boot。
2. Spring Boot 复用当前 `access-token` 鉴权。
3. 未登录用户不能访问 `/admin/ai/chat`。
4. Python Agent 只允许 Spring Boot 服务调用。

## 10. 数据安全需求

敏感字段默认不返回：

| 表 | 字段 |
| --- | --- |
| `user_info` | `password`、完整 `phone` |
| `system_user` | `password`、完整 `phone` |
| `lease_agreement` | `identification_number`、完整 `phone` |
| `view_appointment` | 完整 `phone` |

如果确实需要按手机号或姓名筛选，应允许作为查询条件，但返回结果需要脱敏。

## 11. 产品验收清单

第一版完成后应满足：

1. 能回答预约、租约、房源、租金、浏览热度五类核心问题。
2. 能对不支持的问题明确拒答。
3. 能展示 SQL 和表格。
4. 能生成 ECharts 可用配置。
5. 能输出不超过 200 字的经营总结。
6. 所有 SQL 均只读且带安全限制。
7. 查询失败时有明确错误提示。
