# 03 · 技术架构与模块设计

## 1. 系统架构

AptGuide 分两阶段建设。第一阶段先做独立应用，验证 Agent 和界面体验；第二阶段再接入现有公寓租赁系统。

### 1.1 第一阶段：独立应用架构

```text
┌─────────────────────────────────────────────────────────────┐
│ AptGuide Web UI                                             │
│  - 聊天窗口 / 房源卡片 / 操作按钮 / 预约确认                │
└──────────────────────────────┬──────────────────────────────┘
                               │ HTTP /api/chat
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ AptGuide (FastAPI + LangGraph)                              │
│                                                             │
│  ┌─────────┐   ┌──────────┐   ┌──────────────┐             │
│  │ api/    │ → │ agent/   │ → │ tools/       │             │
│  │ chat.py │   │ graph    │   │ mock / httpx │             │
│  │ stream  │   │ Redis    │   └──────────────┘             │
│  └─────────┘   │ state    │ → ┌──────────┐                 │
│                │          │   │ vector/  │ → Milvus         │
│                └──────────┘   └──────────┘                 │
└─────────────────────────────────────────────────────────────┘
```

第一阶段允许工具层使用 Mock / Stub 数据，目的是让聊天界面、Agent 编排、RAG、工具调用协议、预约确认和评测体系先独立跑通。所有 Mock 响应必须遵守第二阶段的真实响应模型。

### 1.2 第二阶段：系统集成架构

```text
┌─────────────────────────────────────────────────────────────┐
│ rentHouseH5 (Vue3 + Vant)                                   │
│  - 聊天页面 / 房源卡片 / 操作按钮                           │
└──────────────────────────────┬──────────────────────────────┘
                               │ HTTPS + JWT
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ lease (Spring Boot)                                          │
│  - 用户鉴权                                                  │
│  - 业务接口（房源、预约、租约、浏览历史）                    │
│  - 内部 AI 网关 /app/ai/chat                                 │
└──────────────────────────────┬──────────────────────────────┘
                               │ HTTP + X-Internal-Token + X-User-Id
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ AptGuide (FastAPI + LangGraph)                              │
│                                                             │
│  ┌─────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐  │
│  │ api/    │ → │ agent/   │ → │ tools/   │ → │ lease    │  │
│  │ chat.py │   │ graph    │   │ httpx    │   │ (Java)   │  │
│  │ stream  │   │ Redis    │   └──────────┘   └──────────┘  │
│  └─────────┘   │ state    │                                │
│                │          │ → ┌──────────┐   ┌──────────┐  │
│                │          │   │ vector/  │ → │ Milvus   │  │
│                └──────────┘   │ pymilvus │   │          │  │
│                               └──────────┘   └──────────┘  │
└─────────────────────────────────────────────────────────────┘
                               ▲
                               │ 离线
                  ┌────────────┴────────────┐
                  │ scripts/sync_room_vectors│
                  │ scripts/seed_kb         │
                  └─────────────────────────┘
```

第二阶段前端不直接调用 AptGuide。`rentHouseH5` 只调用 `lease /app/ai/chat`，由 `lease` 完成 JWT 校验、用户身份获取、统一异常处理和响应包装，再通过内部 token 调用 AptGuide。

## 2. 模块划分

| 模块 | 路径 | 职责 |
|------|------|------|
| API | `src/aptguide/api/` | FastAPI 路由、依赖注入、请求 / 响应模型绑定 |
| Stream | `src/aptguide/api/stream.py` | SSE 流式响应，输出节点进度、工具状态、最终卡片 |
| Web UI | `src/aptguide/ui/` 或独立前端目录 | 第一阶段独立聊天页面、房源卡片、预约确认组件 |
| Agent | `src/aptguide/agent/` | LangGraph 状态、节点、提示词、对话编排 |
| Tools | `src/aptguide/tools/` | 调用 Java 内部接口的 HTTP 客户端 |
| Vector | `src/aptguide/vector/` | Milvus 客户端、房源索引、KB RAG |
| Memory | `src/aptguide/memory/` | Redis 会话状态、最近推荐、待确认操作、短期偏好 |
| Core | `src/aptguide/core/` | 配置（pydantic-settings）、JSON 日志、错误 |
| LLM | `src/aptguide/llm/` | OpenAI 兼容客户端、结构化输出 schema |
| Knowledge | `src/aptguide/knowledge/` | 意图清单、待入库的 FAQ / 规则原文 |
| Schemas | `src/aptguide/schemas/` | Pydantic 请求 / 响应 / 工具入参出参模型 |
| Security | `src/aptguide/security/` | 身份透传、敏感字段过滤 |

## 3. 关键数据流

### 3.0 独立应用对话流程

```
1. 用户打开 AptGuide Web UI
2. 前端 POST /api/chat，携带 session_id + message
3. agent.graph 执行 intent_node / slot_node / tool_node / reply_node
4. memory 层读取 Redis 中的 last_recommendations / pending_confirmation / slots
5. tools 层按配置选择 mock backend 或 lease HTTP backend
6. 返回 reply + cards + actions + pending_confirmation + sources
7. Web UI 渲染自然语言、房源卡片、操作按钮和来源
```

### 3.0.1 SSE 流式响应流程

第一阶段独立 UI 和第二阶段 H5 均可使用 SSE。非流式 `/api/chat` 保留，便于测试和降级。

```text
1. 前端 POST /api/chat/stream 或 GET /api/chat/stream?session_id=...
2. AptGuide 返回 text/event-stream
3. 事件序列：
   - message_received       收到用户消息
   - intent_detected        识别到意图
   - slot_updated           槽位抽取 / 合并完成
   - tool_call_started      开始调用 Milvus / Java 工具
   - tool_call_finished     工具返回
   - answer_delta           LLM 增量文本
   - final                  最终结构化响应，含 cards / actions / sources
   - error                  可恢复或不可恢复错误
```

### 3.1 找房流程

```
1. lease /app/ai/chat                                 (用户态 JWT)
2. AptGuide /api/chat                                 (X-User-Id + X-Internal-Token)
3. agent.graph: intent_node → 识别为 room_search
4. agent.graph: slot_node  → 抽取 max_rent / district / payment_type / tags
5. 槽位不足 → ask_node 追问，结束本轮
6. 槽位充足 → vector.room_index.search    (语义召回 room_ids)
7. tools.room.search(room_ids, filters)   (Java 精确过滤)
8. agent.graph: rerank_node → 选 top-3
9. agent.graph: reply_node  → LLM 生成推荐理由
10. 返回 reply + cards + actions
```

### 3.2 预约流程

```
1. 用户："帮我预约 302 明天下午"
2. agent.graph: intent_node → appointment_create
3. agent.graph: slot_node  → room_id=3001, time="明天下午"
4. 时间不精确 → ask_node 追问 "明天下午有 14/15/16 三个时段"
5. 用户："15 点"
6. slot 齐全 → 进入 confirm_node，生成操作摘要返回
7. 等待用户确认 → 状态 pending_confirmation
8. 下一轮用户："确认" → tools.appointment.create(...)
9. 返回结果 + 后续动作（查看预约 / 改期）
```

### 3.3 FAQ 流程

```
1. agent.graph: intent_node → kb_qa
2. vector.kb_search.search(query, top_k=3)
3. 召回 score < 阈值 → 回退（"暂无明确答案"）
4. 召回有效 → reply_node 把召回片段塞入提示词
5. 返回 reply + sources（条目 ID 列表）
```

## 4. 进程与端口

- AptGuide API：默认 `0.0.0.0:8100`，HTTP，明文（依赖网关 / mesh 做 mTLS）。
- AptGuide Web UI：第一阶段可与 FastAPI 同进程提供静态页面，也可独立运行在 Vite 开发端口；正式集成后入口迁移到 `rentHouseH5`。
- Milvus：默认 `127.0.0.1:19530`。
- lease：默认 `127.0.0.1:8080`。

## 5. 配置

`src/aptguide/core/config.py` 用 pydantic-settings 从 `.env` 加载。所有外部依赖的连接信息（LLM、Milvus、lease）都通过环境变量注入，不写死。完整字段见 `.env.example`。

新增配置建议：

| 配置 | 用途 | 默认 |
|------|------|------|
| `REDIS_URL` | 会话状态、待确认操作、短期偏好缓存 | `redis://127.0.0.1:6379/1` |
| `TOOL_BACKEND` | `mock` / `lease`，控制工具层后端 | 第一阶段 `mock`，第二阶段 `lease` |
| `ENABLE_SSE` | 是否启用流式响应 | `true` |
| `PROMPT_VERSION` | 当前提示词版本标签 | `v1` |
| `RAG_RERANK_ENABLED` | 是否启用重排 | `false` |

## 6. 日志与可观测

- 日志：JSON 格式（`python-json-logger`），字段含 `request_id`、`session_id`、`user_id_hash`、`intent`、`tool_calls`、`latency_ms`。
- LLM 观测：记录 `model`、`prompt_version`、`input_tokens`、`output_tokens`、`temperature`、`llm_latency_ms`。
- RAG 观测：记录 `query_rewrite`、`top_k`、`retrieval_scores`、`rerank_scores`、`fallback_reason`。
- Tool 观测：记录工具名、入参摘要、响应状态、错误码、重试次数、耗时。
- Tracing：MVP 使用 `request_id` 串联日志；第二阶段可接入 LangSmith 或 OpenTelemetry。
- 指标：MVP 暂不接 Prometheus，先记录到日志，运维侧收集。

## 7. 错误分类

| 来源 | 错误码示例 | 处理 |
|------|------------|------|
| 用户输入 | `VALIDATION_ERROR` | 返回 400 + 友好提示 |
| LLM 异常 | `LLM_TIMEOUT` / `LLM_INVALID_OUTPUT` | 重试一次或回退到模板回答 |
| Milvus | `VECTOR_UNAVAILABLE` | 跳过语义召回，仅走 Java 显式过滤 |
| Java 工具接口 | `TOOL_4XX` / `TOOL_5XX` | 直接传达失败，不掩盖、不伪造 |
| 内部 | `INTERNAL_ERROR` | 返回 500 + 记录堆栈 |

## 8. 部署形态

- 第一阶段独立演示：启动 AptGuide API + 独立 Web UI，可使用 Mock / Stub 工具数据。
- 第二阶段系统集成：AptGuide 作为内部 AI 服务部署，由 `lease` 调用，不直接暴露给公网前端。
- 容器化：Dockerfile（后续提供），多阶段构建。
- 本地编排：第二阶段建议提供 Docker Compose，一键启动 MySQL、Redis、MinIO、Milvus、AptGuide，按需要再加入 `lease` 和 `AptInsight`。
- API 启动：`uv run uvicorn aptguide.main:app --host 0.0.0.0 --port 8100 --workers 2`。
- 健康检查：`GET /health` 返回 `{"status":"ok"}`，依赖检查（Milvus / lease）单独 `GET /health/deps`。
- 离线任务：`scripts/sync_room_vectors.py` 由运维侧定时（如每小时）触发。

## 9. 跨项目交互

```text
租客 C 端:
rentHouseH5 → lease web-app /app/ai/chat → AptGuide → lease internal tools → MySQL

运营 B 端:
rentHouseAdmin → lease web-admin /admin/ai/chat → AptInsight → MySQL readonly

数据闭环:
AptGuide 产生 AI 找房 / 预约行为 → lease 记录业务数据和来源 → AptInsight 分析 AI 转化效果 → 运营调整房源标签 / 规则知识库 → Milvus 同步 → AptGuide 推荐效果提升
```

| 项目 | 交互方式 | 说明 |
|------|----------|------|
| `rentHouseH5` | 第二阶段调用 `lease /app/ai/chat` | 渲染聊天、房源卡片、操作按钮和确认弹窗 |
| `lease web-app` | 调 AptGuide `/api/chat` | 校验租客登录态，透传 `X-User-Id`、`X-Request-Id`、内部 token |
| `lease internal tools` | 被 AptGuide 调用 | 提供房源搜索、房源详情、预约创建、租约查询、浏览历史查询 |
| `rentHouseAdmin` | 后续运营入口 | 维护房源标签、规则知识库，查看 AI 运营指标 |
| `AptInsight` | 不直接调用 AptGuide | 通过 MySQL 只读分析 AI 助手带来的业务效果 |

## 11. 大模型应用技术路线

这些能力用于支撑大模型应用开发岗位的核心能力展示，按优先级分为 MVP 必做和增强路线。

| 能力 | 阶段 | 价值 | 落点 |
|------|------|------|------|
| LangGraph 任务型 Agent | MVP | 将意图、槽位、工具、确认、回复拆成可观测节点 | `agent/graph.py` |
| RAG 检索增强 | MVP | 房源语义召回、规则问答、来源可追溯 | `vector/room_index.py`、`vector/kb_search.py` |
| Tool Calling 安全层 | MVP | 业务工具白名单、参数校验、错误映射、超时重试 | `tools/`、`schemas/` |
| Redis 会话状态 | MVP | 支持“第一个房源”“确认”等多轮任务状态 | `memory/` |
| SSE 流式响应 | MVP | 提升聊天体验，展示工具调用进度和最终卡片 | `api/stream.py` |
| Agent Eval | MVP | 评估意图、槽位、工具调用、RAG 命中和安全确认 | `evals/` |
| Prompt / Schema 版本管理 | MVP | Prompt 可回滚、可对比、可评测 | `agent/prompts/` |
| JSON 日志 + trace_id | MVP | 定位一次 Agent 错误的全链路原因 | `core/logging.py` |
| Docker Compose | 集成阶段 | 固化 MySQL、Redis、MinIO、Milvus、AI 服务联调环境 | `docker-compose.yml` |
| MCP 工具适配 | 增强路线 | 将 Java 工具和检索能力标准化为 MCP tools | `tools/mcp/` |

不作为 MVP 前置条件：

- Kafka / RocketMQ：仅在房源上架、下架、改价需要事件驱动同步时引入。
- Kubernetes / Nacos：当前阶段不需要服务治理复杂度。
- 多模态图片理解：可作为后续“看图问房源”能力，不影响当前找房助手主链路。
