## 阅读顺序建议

- **首次接触**：01 → 02 → 03 → 08，建立对项目目标、整体形态和分阶段交付方式的认识。
- **写代码前**：03 → 04 → 05 → 06，了解模块边界和外部契约。
- **生成 RAG 数据前**：06 → 09，确认 Collection、字段、数据格式和生成顺序。
- **写测试前**：07，对照评测和契约要求。
- **了解已测内容**：优先读 `../docs/test-coverage-summary.md`，再按需读 `../docs/test-report-2026-05-05.md`。

## 维护原则

- 文档先行：架构决策先在文档中表达，再落实到代码。
- 小步更新：每次 PR 涉及范围、契约、安全规则的变更都同步修订对应文档。
- 不堆术语：用具体接口、字段、对话样例代替形容词。
