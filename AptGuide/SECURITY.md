# SECURITY.md

本文件汇总 AptGuide 项目的安全约束。所有变更（提示词、工具接口、检索逻辑）都必须遵守这里列出的规则。

## 安全基线

AptGuide 是面向 **C 端租客** 的对话服务，比 B 端更需要谨慎处理：

1. 用户不可信——任何用户输入都不能直接作为权限或身份依据。
2. AI 不可信——LLM 的工具调用参数必须由后端再校验一次。
3. Milvus 不是权威数据源——召回结果只用于"找候选"，不用于"出结论"。

## 数据访问

| 类型 | 访问方式 | 备注 |
|------|---------|------|
| 房源 / 公寓（公开） | Milvus 召回 + Java 精确过滤 | Milvus 可缓存简要文本 |
| 用户租约 | 仅 Java 接口，按当前登录用户 ID 过滤 | AptGuide 不缓存、不写库 |
| 用户预约 | 仅 Java 接口，按当前登录用户 ID 过滤 | 同上 |
| 用户浏览历史 | 仅 Java 接口，按当前登录用户 ID 过滤 | 同上 |
| 合同全文 / 支付 / 凭证 | **不通过 AptGuide** | Java 直接返回前端 |
| 手机号 / 身份证 / 密码 | **永不进入 AptGuide** | Java 不应在工具响应中返回 |

## 身份透传

- 移动端 → `lease` 调用 `/app/ai/chat` 时携带用户 JWT。
- `lease` 校验 JWT 后，调用 AptGuide `/api/chat`，在请求头注入：
  - `X-Internal-Token`：服务间共享密钥
  - `X-User-Id`：经服务端解析的用户 ID
- AptGuide **绝不接受** 来自客户端 body / query 的 `userId` 字段；只信任 header 中由 `lease` 注入的值。
- 所有调用 Java 工具接口的请求都把 `X-User-Id` 透传回去，由 Java 再次按身份过滤。

## 写操作

涉及创建/修改的工具：

- `appointment.create`
- `appointment.cancel`
- 未来的 `lease.renew_request`、`lease.terminate_request`

执行规则：

1. Agent 先返回结构化的"操作摘要"，停在"等待确认"状态。
2. 用户必须显式确认（"确认预约"、"是的"），才会进入下一轮。
3. 下一轮 Agent 才能调用对应 Java 写接口。
4. 写入失败时，Agent 必须如实回传错误，不重试不掩盖。

## Milvus 内容白名单

允许写入 Milvus 的内容：

- 房源描述、户型、配套、标签、区域、租金区间（公开字段）
- 公寓介绍、地址、配套
- 租房规则、FAQ、流程指引（运营审核过的文案）

**禁止写入** Milvus：

- 任何用户个人信息（手机、身份证、邮箱、地址）
- 合同 / 协议全文
- 支付记录、银行卡号
- 后台管理员账号或令牌
- 内部审计日志

## 服务间通信

- AptGuide 默认监听内网端口（如 `0.0.0.0:8100`）。
- 生产环境使用 service mesh / VPC 限制只允许 `lease` 访问。
- `X-Internal-Token` 用于网关层补充校验，密钥通过 K8s Secret 或配置中心下发，**不进仓库**。

## 提示词与日志

- 提示词不要拼接用户隐私字段。
- 日志默认用 JSON 输出；记录 `request_id`、`user_id`（仅哈希）、意图、工具名、耗时；**不记录用户消息原文，除非用户明确同意**。
- 错误堆栈中如果包含用户输入，需经 `security/redaction` 脱敏后再输出。

## 漏洞反馈

发现安全问题请联系仓库 owner，**不要**在公开 issue 中披露细节。
